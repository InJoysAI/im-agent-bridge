### 风险清单

#### RISK-B001: Runtime 候选能力不完全匹配

| 属性 | 值 |
|------|-----|
| **类别** | 依赖风险 |
| **可能性** | 中 |
| **影响程度** | 高 |
| **风险等级** | 高 |
| **负责人** | 系统开发者 |
| **描述** | NanoBot 作为候选 Runtime 在当前场景下能力不完全匹配（如会话管理、MCP 集成模式等） |
| **缓解措施** | 通过适配器模式保留替换空间，不将 NanoBot 写死为不可替换核心 |
| **应急预案** | 切换到备选 Runtime，确保适配层可快速重写 |

#### RISK-B002: Runtime 与 Bridge 边界混淆

| 属性 | 值 |
|------|-----|
| **类别** | 架构风险 |
| **可能性** | 中 |
| **影响程度** | 高 |
| **风险等级** | 高 |
| **负责人** | 系统开发者 |
| **描述** | NanoBot 自带 Channel / Gateway 能力，可能导致开发者混用 Runtime 入口与系统 Bridge + Gateway 入口 |
| **缓解措施** | 明确 Runtime 不承担主入口职责，Bridge 仅对接 Gateway (BR-023) |
| **应急预案** | 代码审查中严格检查 Runtime 不直接暴露 Telegram 端口 |

#### RISK-B003: MCP 工具暴露范围不可控

| 属性 | 值 |
|------|-----|
| **类别** | 依赖风险 |
| **可能性** | 中 |
| **影响程度** | 中 |
| **风险等级** | 中 |
| **负责人** | 系统开发者 |
| **描述** | Shopify MCP 默认暴露全部工具，导致第一版执行边界不清 |
| **缓解措施** | MVP 阶段默认全部启用，前提是 MCP 实例本身暴露的是可接受工具 |
| **应急预案** | 如发现不安全工具，通过 MEMORY.md 配置限制工具列表 |

#### RISK-B004: 会话上下文设计过重导致 MVP 膨胀

| 属性 | 值 |
|------|-----|
| **类别** | 范围风险 |
| **可能性** | 高 |
| **影响程度** | 高 |
| **风险等级** | 极高 |
| **负责人** | 项目负责人 |
| **描述** | 会话上下文需求有天然扩展倾向（thread_id, group_id, 多轮记忆等），可能导致 MVP 迟迟无法交付 |
| **缓解措施** | 只保留最小 session 边界（BR-010~BR-015）与轻量上下文（由 Runtime 管理），不做独立记忆系统 |
| **应急预案** | 严格执行 MVP 范围锁定：单渠道、文本消息、单 Runtime |

#### RISK-B005: 后续需求扩展破坏三层骨架

| 属性 | 值 |
|------|-----|
| **类别** | 架构风险 |
| **可能性** | 高 |
| **影响程度** | 高 |
| **风险等级** | 极高 |
| **负责人** | 项目负责人 |
| **描述** | 新需求（多渠道、多 Runtime、富媒体等）可能推翻三层架构设计 |
| **缓解措施** | 严格锁定第一版为单渠道、文本消息、单 Runtime 主链路 (BR-020) |
| **应急预案** | 新需求必须通过 OpenSpec 提案流程评审，评估架构影响后方可实施 |

#### RISK-B006: 群聊共享上下文语义混淆

| 属性 | 值 |
|------|-----|
| **类别** | 产品风险 |
| **可能性** | 中 |
| **影响程度** | 中 |
| **风险等级** | 中 |
| **负责人** | 产品经理 |
| **描述** | 多人在同一群聊提问时共享上下文，可能导致 AI 回复语义混淆 |
| **缓解措施** | MVP 阶段先采用群共享上下文 (BR-013)，后续按实际使用情况评估 |
| **技术层面** | 技术解决方案见 `architecture/risks_and_debt.md` TD-006（引入 `thread_id` 或按用户拆分 session） |
| **应急预案** | 升级为群内按用户拆分 session_id |

#### RISK-B007: 群聊 mention 过滤导致漏响应

| 属性 | 值 |
|------|-----|
| **类别** | 产品风险 |
| **可能性** | 中 |
| **影响程度** | 中 |
| **风险等级** | 中 |
| **负责人** | 运营负责人 |
| **描述** | Bot 开启 `require_mention=true` 后，用户若未显式 `@bot_username`，请求会被 Gateway 入口过滤，可能被误判为“机器人无响应” |
| **缓解措施** | 默认 `require_mention=false`；按 Bot 灰度开启；在群公告中明确 @ 使用规范；日志记录 `inbound skipped: group_no_mention` 便于排查 |
| **应急预案** | 运营回滚配置：`UPDATE bots SET require_mention=false WHERE id=<bot_id>`，恢复全量响应 |

## 🧾 项目债务

### PD-001: 群聊上下文粒度不足

| 属性 | 值 |
|------|-----|
| **类型** | 范围债务 |
| **严重性** | 中 |
| **描述** | MVP 阶段群聊共享上下文，多人提问时语义可能混淆 |
| **影响** | 群聊场景下 AI 回复质量可能下降 |
| **偿还计划** | 根据实际使用反馈，评估是否在 V2 按用户拆分群聊上下文 |

### PD-002: 单渠道限定

| 属性 | 值 |
|------|-----|
| **类型** | 范围债务 |
| **严重性** | 低 |
| **描述** | 第一版仅支持 Telegram，不支持 WhatsApp、Discord 等渠道 |
| **影响** | 无法覆盖其他 IM 渠道用户 |
| **偿还计划** | 骨架设计已考虑多渠道扩展，后续通过增加 Channel Adapter 实现 |

### PD-003: 仅文本消息支持

| 属性 | 值 |
|------|-----|
| **类型** | 范围债务 |
| **严重性** | 中 |
| **描述** | 第一版仅支持文本消息，不支持图片、文件、富媒体 |
| **影响** | 用户无法发送截图或接收结构化回复 |
| **偿还计划** | 后续版本在标准消息结构中扩展媒体类型字段 |

### PD-004: 无可观测性基础设施

| 属性 | 值 |
|------|-----|
| **类型** | 流程债务 |
| **严重性** | 中 |
| **描述** | MVP 阶段仅有基础日志，无统一 trace_id、无业务指标采集、无告警系统 |
| **影响** | 排障依赖人工日志分析，无法快速定位链路问题 |
| **偿还计划** | 按需实现可观测性增强（统一 trace_id、指标采集） |
